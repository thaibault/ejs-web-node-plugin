ejs-web-node-plugin 1.0.439

Project status

Use case

This web-node plugin renders EJS templates found in your application into static files. Templates have access to the complete web-node configuration, so you can generate e.g. configuration files for other services, static HTML pages or scripts from one central configuration.

Features included:

  • Renders every "*.ejs" file next to itself without the extension, e.g. "nginx.conf.ejs" becomes "nginx.conf".
  • In-place replacement of files which are templates themselves.
  • Nested includes with their own local variables.
  • Configurable template scope with utilities, evaluated expressions and plain values.
  • Re-rendering after configuration changes and removal of generated files on shutdown.

Content

Installation

Install the plugin next to web-node. web-node discovers every installed package whose name ends with "-web-node-plugin" automatically:

yarn add web-node ejs-web-node-plugin

Example

All values of the scope are available via the locals name "_". A template "greeting.txt.ejs" in your application directory:

Hello from <%- _.configuration.name %>!

Rendered at <%- _.now.toISOString() %>.

<%- await _.include('footer.txt', {year: _.now.getFullYear()}) %>

Enable rendering on startup and after configuration updates in your application's "package.json". The result is written to "greeting.txt":

{
    "webNode": {
        "ejs": {
            "renderAfterConfigurationUpdates": true
        }
    }
}

Without this option nothing is rendered automatically. Other plugins can then trigger rendering via "services.ejs.render(state)".

Configuration

All options live below "webNode.ejs":

  • "extensions": File endings to treat as templates. Defaults to ".ejs" and ".html.js".
  • "locations.include" and "locations.exclude": Directories to search and to skip. "node_modules", "src", "log", "database" and similar folders are excluded by default.
  • "locations.inPlaceReplacements": Files rendered into themselves instead of a new file.
  • "cache" and "cacheInPlaceReplacements": Skip rendering if a result already exists.
  • "options": Options passed to EJS, e.g. "localsName" (default "_").
  • "scope": Values available in templates. "plain" holds static values, "evaluation" and "execution" hold JavaScript expressions and statements evaluated once per rendering ("async_*" variants may be awaited). By default configuration, plugins, "now" and the clientnode utilities ("array", "string", "object", …) are provided.
  • "renderAfterConfigurationUpdates": Render on startup and after each configuration change. Defaults to "false".
  • "reloadEntryFiles" and "reloadSourceContent": Search templates and read their content again on each rendering.

Hooks and services

  • "preEjsRender": Runs before rendering. Return modified "entryFiles" or "scope".
  • "postEjsRender": Runs after all templates are written.
  • "services.ejs.render": Triggers rendering of all templates.
  • "services.ejs.renderFactory": Creates a render function for single files.
